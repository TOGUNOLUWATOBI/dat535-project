# DAT535 — Kolumbus and Agder timetable history

A data engineering pipeline for Entur's national NeTEx timetable exports,
filtered to **Kolumbus** (`KOL`, Rogaland) and **Agder Kollektivtrafikk**
(`AKT`). It keeps the raw source with full provenance, builds validated Parquet
tables with Spark (Bronze → staging → Silver → Gold), tracks how routes change
between exports, and shows the result in a Streamlit GUI.

**Data.** Nine historical exports dated the 15th of each month (January–September
2026), calendar-support exports that fill whole service months, and scheduled
ingestion from November 2026. On 10 November 2026 the school-server rebuild
completed 22 jobs and passed full-month coverage for January–November; January–
September holds 1,918,707 planned departures over all 273 days
([verified runs](docs/evidence/verified_runs.md)).

These are **published plans**, not records of what vehicles actually ran. The
GUI shows service dates up to today (Norway) by default; future plans can be
switched on with **Include future timetable plans**.

## Quick start

Requires Python 3.11+ and, for Spark, Java 17.

```bash
# Environments (Spark processing and the GUI are kept separate on the server)
python3 -m venv ~/spark-env      && ~/spark-env/bin/pip install -r requirements.txt
python3 -m venv ~/dat535-gui-env && ~/dat535-gui-env/bin/pip install -r requirements.txt

# Process an ingested snapshot, build route history, start the GUI
bash scripts/run.sh processing --manifest /path/to/metadata/manifest.json --data-root /srv/dat535/data
bash scripts/run.sh history --data-root /srv/dat535/data
bash scripts/run_gui.sh                          # http://localhost:8501
```

## Pipeline

| Layer | What it holds |
| --- | --- |
| **Bronze** | Selected KOL + AKT XML and national stops in a checksum-verified ZIP, with source identity, lineage and validation reports |
| **Staging** | 16 NeTEx entity tables as Parquet, one row per source occurrence, with file and frame context |
| **Silver** | Resolved references, typed times, expanded calendars; invalid rows kept with reason codes and copied to `quarantine_*` |
| **Gold** | Daily line and network service, reconciled to Silver; published only if the quality gate passes |
| **History** | Line versions (SCD Type 2), appearances, removals, route and stop changes, and operator-verified renumberings |

Every stage is checkpointed in SQLite: a completed output is reused only when
its input, code and files are unchanged, and failed attempts are kept as
evidence. Transport facts live in Parquet; SQLite holds only processing state
(`python3 -m pipeline.checkpoints --state /srv/dat535/data/pipeline_state.sqlite3`
lists every attempt).

**Quality gate.** Before Gold is written, Silver is checked against
`config/quality_thresholds.json`: any rejected row gives a warning; more than 1%
quarantined journeys, passing times or service occurrences, any ambiguous
reference, a missing or unexpected provider, or no accepted service for a
provider stops publication. The result is saved with each Gold output.

## Commands

All Spark work goes through `scripts/run.sh` (run it without arguments for the
list). It uses `~/spark-env` and the project's Java 17 from
`~/dat535-runtime/java17.json`, and unsets `SPARK_HOME` so the bundled Spark 4.2
is used. Override with `DAT535_SPARK_PYTHON` and `DAT535_JAVA_METADATA`.

| Command | Purpose |
| --- | --- |
| `processing` | One snapshot through staging, Silver and Gold (`--date`, `--all-snapshots`, `--through staging\|silver`) |
| `rebuild` | Whole-month plans for every registered snapshot, one Spark process per job |
| `history` | Route changes across all completed snapshots (`--force` to rebuild) |
| `inspect` | Read route history: `summary`, `candidates`, `month`, `line`, `date` |
| `quality-report` | Before/after Silver quality table and gate results |
| `quality-trace` | Trace real journeys from source XML through Silver and Gold |
| `tests` | The full test suite, including Spark tests |

```bash
bash scripts/run.sh inspect --data-root /srv/dat535/data line AKT 55
bash scripts/run.sh inspect --data-root /srv/dat535/data date AKT 55 2026-07-20
bash scripts/run.sh quality-report --data-root /srv/dat535/data --markdown docs/evidence/quality_report.md
bash scripts/run.sh quality-trace --data-root /srv/dat535/data --snapshot 2026-02-15 --markdown docs/evidence/quality_traces.md
```

### Ingestion

Ingestion needs only the standard library:

```bash
# Historical months (use a new output directory)
python3 -B -u -m pipeline.ingestion.generate_provider_dataset \
  --providers KOL AKT --from-month 2026-01 --to-month 2026-09 \
  --output entur_netex_snapshots/kol_akt_rebuild --zip-only --remove-national-after-validation

# Yesterday's export (what the scheduled workflow runs); --date YYYY-MM-DD for another day
python3 -B -u -m pipeline.ingestion.poll_entur_netex --zip-only --remove-national-after-validation

# A ZIP you already have
python3 -B -u -m pipeline.ingestion.ingest_local_zip --source /path/to/source.zip --date 2026-01-15 --zip-only
```

Every run writes to a new folder and refuses an existing one. National ZIPs are
removed only after the selected data validates; failed sources and original
uploads are always kept. Timeouts and HTTP 408/429/5xx are retried three times;
a 404 fails instead of picking another date. Storage tools:
`python3 -m pipeline.storage.zip_bronze --help` and
`python3 -m pipeline.storage.maintenance --help`.

### Full-month rebuild

A mid-month export does not cover the first days of its month, so
`prepare_monthly_support` adds a validated early export for each month
(marked `calendar_support`; it fills daily plans but is not a route-history
observation). To rerun, resume or extend the school-server rebuild:

```bash
python3 -B -u -m pipeline.ingestion.prepare_monthly_support \
  --providers KOL AKT --from-month 2026-01 --to-month 2026-10 \
  --output /srv/dat535/data/bronze/entur/calendar_support_2026_01_09 \
  --remove-national-after-validation

bash scripts/run.sh rebuild \
  --data-root /srv/dat535/data \
  --primary-manifest /srv/dat535/data/bronze/entur/kol_akt_2026_01_09/manifest.json \
  --support-plan /srv/dat535/data/bronze/entur/calendar_support_2026_01_09/calendar_support_plan.json \
  --remove-national-after-validation
```

Progress is recorded in `rebuilds/monthly-*/manifest.json`; rerun the same
command to resume. Each worker gets a 2 GiB Java heap (`--driver-memory` or
`DAT535_DRIVER_MEMORY` to change it). The rebuild is complete only when every
date is covered for both providers.

## Automation

[`ingest-netex.yml`](.github/workflows/ingest-netex.yml) runs on pushes to `main`,
manual dispatch and cron `23 8 */3 * *` (08:23 UTC on days 1, 4, 7, … of each
month, so not exactly every 72 hours) on a self-hosted runner labelled
`self-hosted, linux, dat535`.

Each run checks free space, runs the ingestion tests, ingests yesterday's
Oslo-dated export, consolidates verified duplicate storage, runs the Spark tests,
processes the snapshot, updates route history and restarts the GUI. Any failure
stops the run before the GUI restarts. Only metadata reports are uploaded to
GitHub (artifact kept 30 days).

**Runner setup.** Register a Linux self-hosted runner (Settings → Actions →
Runners) with the extra label `dat535`, install it as a service
(`sudo ./svc.sh install && sudo ./svc.sh start`), and set the repository
variable `DAT535_DATA_ROOT` to persistent storage outside the checkout (for
example `/srv/dat535/data`). The workflow refuses a data root inside the
checkout or with less than 2 GiB free. On the school server the service is
`actions.runner.TOGUNOLUWATOBI-dat535-project.dat535-spark.service`.

## GUI

A read-only Streamlit app over Gold and route history; it reads Parquet with
pandas and never starts Spark. `bash scripts/run_gui.sh --restart` runs it in the
background (log: `$DAT535_DATA_ROOT/metadata/gui.log`). It listens on
`0.0.0.0:8501` (all interfaces, including localhost). VS Code or SSH port
forwarding to `http://localhost:8501` still works. For direct school-server
access, open `http://152.94.163.144:8501` when inbound TCP 8501 is allowed by
the school/cloud and host firewalls. The app has no login. Override
`DAT535_DATA_ROOT`, `DAT535_GUI_PORT` and `DAT535_GUI_PYTHON` as needed.

| Page | Shows |
| --- | --- |
| Overview | Departures, active lines, daily mean and coverage for a month, operator and mode |
| Daily service | Departures and active lines per date, with source export and CSV |
| Compare months | Monthly totals, change, daily means, weekday profiles, line gains and losses |
| One line | Service, observed versions, changes and stops for one line |
| What changed | Lines appeared/disappeared between exports, verified explanations, stops no longer served |
| Replaced lines | A verified replacement with old/new departures and the operator source |
| Data checks | Quality-gate results, reconciliation and excluded occurrences |

Each date uses the newest export that covers it for both operators; exports are
never added together and missing lines are not filled from older exports.
Averages divide by all covered calendar days, including days without service.
Data is cached for 60 seconds; **Refresh data** clears it.

## Configuration

| File | Purpose |
| --- | --- |
| `config/quality_thresholds.json` | Rules that decide whether Gold may publish |
| `config/route_renumberings.json` | Line replacements, with operator source evidence |
| `config/route_discontinuations.json` | Discontinued lines, with operator source evidence |
| `.streamlit/config.toml` | GUI theme |

A line missing from the next export is only reported as `disappeared`. It is
called `renumbered_verified` or `discontinued_verified` only when a matching
entry has `verified: true` (a JSON boolean), `verified_by`, a `source_url`, a
`note` quoting the operator and a `to_snapshot`. The reader refuses unknown
fields and duplicates, and a verified entry that matches nothing fails route
history. Changing the thresholds creates a new Gold attempt and keeps the old
one. Never commit credentials.

## Repository layout

```text
app/            Streamlit pages, Gold readers and analysis helpers
config/         Quality thresholds and route-change evidence
pipeline/
  ingestion/    Historical, scheduled, manual and calendar-support ingestion
  processing/   bronze/ (XML → staging), silver/, gold/, service windows
  storage/      ZIP retention, temporary XML restore, verified deduplication
  quality/      Publication gate and independent source-to-Gold checks
  analysis/     Route history and its inspection CLI
  run_snapshot.py, rebuild_monthly.py, batch_worker.py
  checkpoints.py, spark_runtime.py, common.py
scripts/        run.sh (Spark commands) and run_gui.sh
tests/          Unit and Spark integration tests; fixtures.py holds shared test data
docs/           Project definition and report (PDF); evidence/ run records and generated reports
```

Data, Parquet, databases, logs and virtual environments are not in Git. Local
runs write to the ignored `data/`; the school server uses `/srv/dat535/data`:

```text
/srv/dat535/data/
├── bronze/entur/           Raw ZIPs, uploads, lineage and validation
├── staging/entur/          Entity Parquet with source context
├── silver/entur/           Cleaned records, calendars, quarantine_* tables
├── gold/entur/             Published metrics and route history
├── rebuilds/monthly-*/     Batch progress and worker results
├── metadata/               Maintenance reports and GUI log
└── pipeline_state.sqlite3  Checkpoint registry
```
